Developer journey · key phases

Phase 1 · Foundation

Scaffolding for scientific content

Bootstrapped from a Next.js documentation template, then immediately restructured around an MDX content pipeline and SSR. TypeScript strict mode, content-generation scripts, and multi-level navigation were established from the outset.

Phase 2 · Geographic visualization

Bringing the ocean to the browser

Integrated Leaflet + MapLibre + react-leaflet to render the Puget Sound, Salish Sea, and Pacific coast, with D3.js layered on top for custom data-driven overlays. A key detail: the map tile layer uses custom OpenStreetMap vector tiles generated offline and self-hosted in a companion repository, served as static files via GitHub Pages — no dependency on any external tile service.

Custom tiles repo: xanderfehsenfeld.github.io/openmap-tiles-demo — demonstrates end-to-end ownership of the full map tile pipeline.

Phase 3 · High-performance particle rendering

WebGL drifters on a live map

Added Pixi.js (via leaflet-pixi-overlay) to animate thousands of simulated ocean surface drifters in real time — a WebGL rendering pipeline layered directly onto the Leaflet canvas for GPU-accelerated particle motion.

Performance challenge: Initial implementation caused frame-rate drops and UI jank. Particle path geometry was being computed and rendered synchronously on every frame tick, blocking the main JavaScript thread during heavy update cycles.

Solution: Particle paths (the trail lines showing each drifter's history) were refactored to render lazily — computed and drawn only on demand rather than every frame. This decoupled expensive geometry work from the animation loop, keeping the UI thread free and maintaining smooth playback even at scale. A current open PR further extracts all playback state into a dedicated custom React hook.

Phase 4 · Developer experience

Production discipline on a solo project

Introduced Husky git hooks, ESLint with TypeScript-aware rules, Prettier with import sorting, and a clean script enforced on every commit. 39 merged pull requests on a solo project signals deliberate, feature-branch–driven development rather than direct-to-main commits.

Phase 5 · Content platform

More than just maps

Shipped dark/light mode, fuzzy search with term highlighting, auto-generated table of contents, LaTeX math via KaTeX, Mermaid.js diagrams, syntax-highlighted code blocks, and Radix UI primitives — a complete scientific knowledge base that embeds live interactive visualizations in documentation pages.

Technical highlights

  • Three rendering engines, zero conflicts. Leaflet manages tile maps and user interaction; D3 handles data-driven SVG overlays; Pixi.js runs a WebGL particle layer — all coordinated in a single React component tree without mutual interference.
  • Self-hosted vector tiles. Custom OpenStreetMap tiles generated offline and served as static files, eliminating any dependency on external tile APIs and demonstrating full ownership of the map tile pipeline.
  • Lazy rendering for UI thread health. Particle path geometry is computed on demand rather than synchronously per frame — a deliberate architectural choice that keeps animation smooth at scale.
  • Full TypeScript coverage. Type definitions span custom geographic data structures, Leaflet extension types, D3 selections, and Pixi.js display objects — not surface-level typing.
  • Interactive drifter simulation. Users click individual particles to trace forecast paths, or click the map to select and highlight groups by proximity — turning a scientific model into an exploratory spatial tool.
  • MDX-powered scientific documentation. Content pages embed live React components — maps, diagrams, math expressions — directly alongside prose, with SSR for fast load and SEO-ready metadata.
